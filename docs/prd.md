# revmcp 需求文档（PRD）

## 1. 背景与核心目标

运维和研发人员经常需要借助本地 AI Agent（Cursor、Claude Code、Claude Desktop 等）对**受限 Linux 环境**（精简容器、临时授权的 CentOS 7/老旧主机、NAT 内网节点）进行故障排查与操作。这些环境通常：

- 无法从外部主动发起入站连接（无公网 IP、防火墙封锁入站端口）；
- 缺少现代运行时（`glibc` 版本老旧，跑不动 Node.js 18+ / Python 3.10+ / `uv`），精简容器甚至缺少 `ps`/`ss`/`bash`；
- 不允许持久化安装常驻 Agent，要求“拷贝即运行、用完即清理”。

**`revmcp` 目标**：构建一个极简的 Go 反向 MCP 网关（`Hub` + `Agent`），允许一台或多台受限目标机主动向外连接公网/内网中转 `Hub`，并由 `Hub` 统一通过标准 **MCP Streamable HTTP** 协议暴露给用户本地 AI Agent，实现安全、可控、可审计的一拖多远程诊断与操作。

## 2. 功能需求（FR）

| 编号 | 模块 | 需求描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR-01** | 南向接入 | Agent 仅通过出站 `HTTPS/WSS`（默认推荐 443 端口，支持手动指定任意自定义隧道端口，自动支持 `HTTPS_PROXY` 代理）向 Hub 注册，无需在目标机开放任何入站端口。 | P0 |
| **FR-02** | 一拖多路由 | Hub 同时维护多台在线 Agent；支持**单端点聚合访问**（`/mcp` 配合 `target_id` 跨机联调）和**单机隔离访问**（`/mcp/{target_id}` 防止 AI 误操作其他主机）。 | P0 |
| **FR-03** | 容器原生诊断 | Agent 内置纯 Go 实现的 `/proc` 诊断原语（系统负载、内存、进程列表、监听端口），即使容器内无 `ps`/`ss`/`bash` 也可正常排查。 | P0 |
| **FR-04** | 受控文件读取 | 支持按偏移量分块读取（`read_file_chunk` / `offset`）、读取文件尾部（`tail_lines`）及正则检索（`grep_file`），禁止一次性吐出超大文件或读取阻塞设备文件。 | P0 |
| **FR-05** | 命令执行与取消 | 支持无状态一次性命令执行（`exec_command`），支持超时强制查杀进程组、客户端点击停止时联动取消远端进程；支持可选的有状态持久化 Shell 会话（`shell_session`）。 | P0 |
| **FR-06** | 纵深安全管控 | 北向支持 Bearer Token + Scope 鉴权；南向支持短效节点注册凭证；**Agent 端强制具备启动级权限锁**（`--mode readonly \| restricted \| full`），默认 `readonly`。 | P0 |
| **FR-07** | 全链路审计 | Hub 将每一次工具调用（调用者、时间、目标机、命令/参数、决策、退出码、耗时）以 JSONL 格式落盘审计。 | P0 |
| **FR-08** | 临时授权清理 | Agent 支持 `--ttl` 自动退出、接收 Hub 远程下线/自毁指令，退出时支持可选自删除磁盘二进制文件，不留残留。 | P1 |

## 3. 非功能需求（NFR）

- **极致兼容性**：Agent 使用 `CGO_ENABLED=0` 全静态编译，无任何动态库依赖，支持 Linux `amd64`/`arm64`，可在 CentOS 7（`glibc 2.17` / kernel 3.10）、Alpine、Scratch/Distroless 容器直接运行（Agent 模块兼容 Go 1.23 编译，可覆盖更老内核环境）。
- **资源占用**：Agent 单文件体积 `< 10MB`（开启 `-s -w` 裁剪），空载常驻内存 `< 20MB`。
- **带宽与上下文防爆**：单次工具输出在 Agent 端即强制截断（默认上限 `32KB`，可调最大 `128KB`），严禁将百 MB 日志通过隧道传回 Hub 或撑爆 LLM 上下文。
- **断线自愈**：支持 NAT/防火墙 60 秒静默断连探测（心跳 10s，超时 30s），Agent 端指数退避重连，新连接自动平滑接管同 `target_id` 旧连接。

## 4. 明确非目标（Out of Scope）

- 不构建复杂的 Web 管理控制台 UI（首期仅提供轻量 CLI / Admin JSON API）；
- 不取代 Zabbix/Prometheus 做长期指标采集与告警；
- 不在目标机 Agent 内嵌任何 MCP 协议栈（避免协议升级导致需要批量替换目标机二进制）。
