## 这版有什么变化

- **一个工具上传和下载。** MCP 的整文件传输统一为 `file`，用 `action=upload` 或 `action=download`。CLI 继续使用 `revmcp-hub file upload` 和 `revmcp-hub file download`。查看日志尾部或文件片段仍用 `read_file`。
- **文件可自动压缩传输。** CLI 上传和 Agent 下载在 gzip 能减小负载时使用压缩。接收端还原原文件并校验 SHA-256。单文件上限仍是原始大小 **10 MB（10,000,000 字节）**，默认拒绝覆盖。
- **沿用已有权限。** 下载使用 `read`。上传需要 `full` Agent 和 `exec:full` 或 `exec:session`，并遵守 Agent 的文件系统权限和敏感路径保护。README 增加了完整的 Scope 与 Agent Mode 表。

## 从 v0.2.0 升级

1. 使用新文件工具需要一起升级 Hub、目标 Agent 和传输 CLI。旧 Agent 可继续提供诊断和命令执行。
2. 从 Agent 的启动命令或服务单元移除 `--upload-dir`。直调 MCP 的客户端将 `upload_file`、`download_file` 换成 `file`，并传对应的 `action`。
3. Hub 的默认策略或 profile 如有 `file:upload`，请在重启前移除或按用途改用执行 Scope。已签发的渠道仍能加载，原有其他权限继续生效。仅凭 `file:upload` 已无法上传，需要用合适的执行 Scope 签发并切换渠道。

## 下载与验证

Assets 提供 Linux amd64 Hub/CLI、Linux amd64 和 arm64 Agent，以及 `SHA256SUMS`。真实 Agent 端到端测试覆盖 10 MB 压缩往返、超限、摘要不一致和权限拒绝。
